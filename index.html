CLI-утилита на языке Rust

Быстрый анализ и фильтрация логов Nginx в терминале.

Консольный инструмент для системных администраторов и разработчиков. Разбирает файл с логами строка за строкой, проверяет корректность полей и собирает статистику по запросам без лишней нагрузки на память.

Установка и запуск Исходный код
kaerisetsu@dev:~ — log_analyser --file access.log

Зачем нужен отдельный парсер

Веб-сервер Nginx фиксирует каждый входящий запрос в текстовом файле access.log. Когда трафика много, такие файлы разрастаются до десятков гигабайт.

Что такое Nginx и зачем читать его логи

Nginx — популярный веб-сервер, через который работает значительная часть сайтов в сети. Каждое обращение к странице, картинке или API записывается в журнал в формате Combined Log Format.

Разбор этих записей помогает вовремя замечать ошибки сервера, находить медленные запросы и отслеживать автоматические сканеры, которые перебирают адреса админ-панелей и служебных файлов.

Чем это лучше обычного grep

grep ищет простое совпадение символов по всей строке. Если искать код 404, он выдаст и те запросы, где эти цифры попали в размер ответа (200 4040) или строку User-Agent. log_analyser разбирает структуру записи на поля и проверяет строго код статуса, метод или IP.

Работа с большими файлами без зависаний

Скрипты на Python или Node.js часто читают файл целиком в оперативную память. На логе размером 30–50 ГБ это приводит к нехватке памяти и аварийному завершению процесса. Утилита читает данные потоком, удерживая минимальный объем ОЗУ.

Как устроена программа

Проект разделен на независимую библиотеку обработки (src/analyze_logs/) и консольную оболочку (src/main.rs).

01 / Конфигурация

Сборка параметров через паттерн Builder

Настройка анализатора вынесена в структуру Analyser. Методы .lines(), .with_filters() и .add_filter() позволяют последовательно собрать набор условий фильтрации перед началом чтения файла. Это упрощает добавление новых фильтров без переписывания основного цикла.

02 / Потоковое чтение

Ленивый итератор LogIterator

Вместо создания большого списка всех записей в памяти реализован собственный итератор LogIterator поверх буферизированного чтения BufReader. Программа берет одну строку, парсит её, прогоняет через фильтры и сразу выводит результат. Расход памяти остается постоянным — O(1).

03 / Проверка данных

Валидация полей и обработка ошибок

В реальных логах встречаются обрезанные или поврежденные строки. Функция LogEntry::parse проверяет формат записи: validate_ip контролирует корректность октетов IPv4, а validate_method сверяет HTTP-метод со списком стандартных методов (GET, POST, PUT, DELETE и др.). Некорректные строки отбрасываются через ParseError без падения программы.

Возможности утилиты

Инструменты для повседневной проверки логов и быстрого поиска причин сбоев.

Цветовая разметка вывода

Методы запросов и коды ответов подсвечиваются разными цветами в терминале. Используя встроенную библиотеку, пользователь может менять цвета вывода по своему усмотрению.

Сводная статистика

Во время прохода по файлу программа считает общее количество обработанных строк, а также число и процентное соотношение успешных ответов и ошибок (коды от 400 и выше).

Топ-3 активных IP-адресов

С помощью хэш-таблицы HashMap подсчитывается количество обращений с каждого IP-адреса. В конце работы выводится тройка адресов с наибольшим числом запросов.

Поиск по произвольной подстроке

Флаг -q / --search включает прямой поиск текста по всей сырой строке лога — удобно для фильтрации по User-Agent, конкретным браузерам или ботам.

Установка и использование

Для сборки понадобится установленный компилятор Rust и пакетный менеджер Cargo.

1. Сборка из исходного кода

bash
git clone https://github.com/cigarette-burn/log-analyser
cd log_analyser
cargo build --release

Установка в систему для Linux и macOS:

bash
sudo ln -sf /полный/путь/к/log_analyser/target/release/log_analyser /usr/local/bin/log_analyser

Добавление в PATH для Windows (PowerShell от имени администратора):

powershell
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\путь\к\log_analyser\target\release", "User")

После добавления пути в Windows перезапустите терминал, чтобы команда log_analyser стала доступна из любой папки.

2. Параметры командной строки

Короткий Полный флаг Назначение
-f --file <PATH> Обязательный. Путь к файлу логов Nginx (access.log).
-n --max-lines <INT> Максимальное число строк для чтения (по умолчанию 1000).
-s --status <INT> Фильтр по точному HTTP-коду ответа (например, 200, 404, 502).
-m --method <STR> Фильтр по HTTP-методу (GET, POST, PUT, DELETE и др.).
-p --path-pattern <STR> Поиск подстроки внутри URL-пути запроса (например, /api/v1).
-i --ip <STR> Фильтр по точному IP-адресу клиента или части подсети.
— --only-errors Показать только ошибки клиента и сервера (статус >= 400).
— --only-success Показать только успешные ответы и редиректы (статус < 400).
-q --search <STR> Поиск произвольного текста по всей строке лога целиком.

3. Примеры запуска

Поиск попыток доступа к закрытой админ-панели (ошибка 403):

log_analyser -f access.log -p /admin -s 403

Проверка успешных POST-запросов к API в пределах первых 5000 строк:

log_analyser -f access.log -m POST -p /api/v1 -n 5000 --only-success
